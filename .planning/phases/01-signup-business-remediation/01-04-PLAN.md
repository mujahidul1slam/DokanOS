## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| member JWT → locations/selling_points INSERTs | Direct RLS-enforced writes via is_business_member policies — first direct member writes in the funnel |
| member JWT → publish_my_storefront | Cross-tenant publish is blocked by the RPC's 4-assertion ownership chain (unchanged) |
| owner UPDATE → businesses.onboarding_completed_at | Marker writable only via the owner/admin UPDATE policy |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Tampering | onboarding marker forgery | low | mitigate | Marker writable only via the existing "Owners can update businesses" policy (can_manage_business_access); members/viewers cannot set it; worst case a co-owner marks done early — a UX state, not a security boundary (RESEARCH Security Domain) |
| T-04-02 | Elevation of Privilege | cross-tenant storefront publish at step 4 | high | mitigate | publish_my_storefront's 4-assertion chain (storefront→store→brand→business) invoked unchanged; storefront_id is the caller's own R4a-reserved row; no new INSERT narrows the assertion surface |
| T-04-03 | Tampering | step 2/3 row shapes | medium | mitigate | Plain member-policy rows with business_id + brand_id from the active context only; no service-role path; the R2d dependency (selling_point_id → selling_points.business_id) is preserved by construction (Release-2 constraint 4) |
| T-04-04 | Spoofing | guard redirect during loading (Pitfall 5) | high | mitigate | Predicates return "wait" while loading; components render null; the loading case is a named seam test |
| T-04-05 | Repudiation | skipped steps leaving no trace | low | accept | Skip semantics are by-design zero-write (D-09); StoresHub CTAs are the durable later path |
| T-04-SC | Tampering (supply chain) | package installs | low | accept | No packages installed in this plan |
</threat_model>
