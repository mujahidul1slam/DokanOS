# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Surfaces in scope** (all decisions D-01…D-18 are LOCKED in `01-CONTEXT.md`; nothing below re-opens them):

1. **`/onboarding` wizard** — new full-page 4-step route (D-10); steps 2–3 skippable (D-09); read-only reserved-URL preview at step 1 (D-11); finish → Dashboard + success toast (D-12). `/welcome` and `/welcome/setup-failed` are retired and redirect to `/onboarding`.
2. **CreateBusinessDialog** — retargeted as the zero-membership landing (D-04) with rewritten reservation copy (D-11/D-12).
3. **StoresHub store lists** — fail-closed (R3): empty business → empty lists + wizard CTA, never "all stores"; connection-truth badges render only real connections.
4. **Business switcher** — per-business only (D-01); no "All businesses" entity anywhere in the UI.

R0 (window-business detection) is an operator-run SQL report — **no UI in this phase**.

### Wizard component structure (agent's discretion — resolved)

Per the anti-god-component rule (audit + CLAUDE.md §2 Simplicity First) and RESEARCH's recommended structure:

```
src/pages/Onboarding.tsx                          # thin shell: route, guards, step state, step indicator
src/components/onboarding/Step1Store.tsx          # store name + reserved-URL preview → create_my_brand_store
src/components/onboarding/Step2Locations.tsx     # first location (skippable, D-09)
src/components/onboarding/Step3SellingPoints.tsx  # first selling points (skippable, D-09)
src/components/onboarding/Step4Storefront.tsx     # publish + finish (sets onboarding_completed_at)
src/components/onboarding/guards.ts               # pure predicates: wait | wizard | create-business (D-17-testable)
```

Each step owns its own form state + submit; the shell owns only current-step, in-flight, and error-banner state. Retired routes `/welcome` and `/welcome/setup-failed` become `<Navigate to="/onboarding" replace />` redirects (D-10); `SetupFailed.tsx` is deleted with its lazy import.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing — icon↔label gaps, badge padding, URL-preview strip inner padding (`p-2`, CreateBusinessDialog:101 idiom) |
| md | 16px | Default element spacing — `space-y-4` between form fields, `p-4` nested panels |
| lg | 24px | Section padding — card content blocks, dialog body top/bottom (`py-4` and up) |
| xl | 32px | Layout gaps — wizard step content vertical rhythm, full-page `py-8` |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing — full-page centered layouts |

Exceptions: none. The retired Welcome.tsx's `space-y-5`/`py-5` (20px) and `p-2.5` (10px) usages die with the page — do not carry them into `/onboarding`. URL-preview and info strips use `p-2` (8px) + `rounded-lg` + `bg-muted/40` + `border-border/30`.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 | 1.5 |
| Label | 14px (`text-sm`) | 600 (`font-semibold`) | 1.5 |
| Caption | 12px (`text-xs`) | 400 | 1.5 |
| Heading | 18px (`text-lg`) | 600 (`font-semibold`) | 1.2 |
| Display | 24px (`text-2xl`) | 600 (`font-semibold`) | 1.2 |

Exactly 4 sizes (12/14/18/24) and 2 weights (400/600):

- **2-weight rule:** 400 + `font-semibold` (600) only. Override shadcn's default `font-medium` (500) on `Label`/`Badge` with `font-semibold`. The retired Welcome.tsx's `font-bold` (700) dies with the page — do not reintroduce.
- **Display** is reserved for the wizard page title ("Set up your store"), with `tracking-tight`. Step and dialog titles use Heading (18px). Helper text, step meta, and URL strips use Caption (12px, `text-muted-foreground`).
- **URL previews** render `font-mono text-foreground` inside the strip (Welcome.tsx:137 idiom); emphasis inside captions uses `<strong className="text-foreground">` (CreateBusinessDialog:104 idiom).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-background` (dark-admin token) | Page background — full-page wizard, app shell, dialog scrims |
| Secondary (30%) | `bg-card`; nested panels `bg-card/60`; info strips `bg-muted/40` with `border-border/40`–`border-border/30` | Cards, wizard info panels, URL-preview strips, dialog surfaces |
| Accent (10%) | `bg-primary` + `text-primary-foreground`; `text-primary` for links/icons | See reserved list below |
| Destructive | `text-destructive` / `destructive` variant | Error alert copy, failure states |
| Success | `bg-emerald-500/10` + `text-emerald-500` | "Connected" badges, published-storefront confirmation, the "Setup Complete" pill (established: Welcome.tsx:105, :125, :165) |

Accent reserved for: primary CTA buttons ("Create store & continue", "Add location & continue", "Add selling point & continue", "Publish storefront", "Finish setup", the dialog's "Create Business" submit), the active wizard step indicator, `text-primary` inline links and empty-state CTAs, and leading icons in step/dialog headers (`Store`, `Building2`, `Globe`). NOT for: skip controls (`outline`/`ghost` variants), badges, body text, or borders.

Zero raw hex — every color resolves through a Tailwind/CSS-variable token. `emerald-500` appears only as the success pairing above (palette class on a `/10` background, never a hex literal).

## UI Considerations

> Populated by the ui-phase UI-consideration probe. Empty-state and error-state COPY lives in `## Copywriting Contract` above — this section covers state coverage and references those rows.

Element kinds detected by the probe (form / list-collection / nav / dialog / static-content / interactive-control) were confirmed by the operator — no additional kinds.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | StoresHub store/location/selling-point/channel/source lists (`list-collection`) | ✅ covered | Zero brand-stores → `useStoresList` returns `[]` **without querying** (fail-closed, D-17 seam test); lists then render the documented empty states + CTAs — never "all stores" |

| loading | StoresHub panels during queries | ✅ covered | Panels render Skeleton rows until store/brand queries settle; empty-state copy renders only after load completes |
| error | Wizard step 1 RPC submit (`form`) | ✅ covered | Inline Alert with the "Couldn't create your store…" copy + retry; `create_my_brand_store` is one transaction, so no partial state can persist on failure |

| zero-one-many | Business switcher (`nav`) | ✅ covered | Switcher lists exactly the joined businesses: one → plain name; many → dropdown; zero → unreachable because the D-04 zero-membership redirect fires first. No "All businesses" pseudo-entity (D-01) |
