# Transitional store model — three id spaces (found 2026-11-01)

The domain revamp's store model is mid-migration. This page records the duality and the RLS landmines it produces. Supersedes nothing; sibling of [onboarding-design.md](onboarding-design.md) and [legacy-pool-semantics.md](legacy-pool-semantics.md).

## The three spaces (as of commit `338461e`)
- **`stores`** — the LEGACY WooCommerce-connections table (`url` NOT NULL, connection status, keys). Populated by Woo connections / legacy sync; nothing in the current UI creates rows. Operational queries scope through it: `useStoresList` → `brands.woo_store_id` → `stores.id` (`useActiveBusinessStoreIds` seam). `products.store_id` and `orders.store_id` FK → `stores`; RLS validates via `user_can_access_store(store_id)`.
- **`brand_stores`** — brand-level store rows (name, store_type, legacy_* back-links). Written by the Brands-page "New Store" dialog (Task 11). Read by `useBusinessContext().brandStores` (useBusinessContext.tsx:144). ALSO legacy — on Task 16's drop list.
- **`order_sources`** — the destination model (Task 8's mapping collapses stores/selling_points/brand_stores/storefronts into it; Task 16 drops the legacy tables).

## RLS landmines found by UI verification (2026-11-01, local stack, fresh signed-up user)
1. **Storefront INSERT** — pipeline documented `store_id=null` for store-less businesses, but `storefronts` INSERT policy was `WITH CHECK user_can_access_store(store_id)` (null fails). **FIXED same day** (`5731853`): brand-scoped fallback legs (membership + `current_business_context()`, per the repo's `activeBusinessRlsContract` static test), pinned by `storefront_brand_rls_test.sql`.
2. **Storefront pages scaffold/publish** — `storefront_pages`/`storefront_page_sections` policies were global `has_role('admin'|'staff')` gates; real signed-up users get NO `user_roles` row (only the first user is admin), so scaffolding silently no-oped and the success toast lied. **FIXED same day** (`5731853`): same brand tenancy one hop through the parent storefront (revives the visual page builder for real accounts) + scaffold/publish now reports outcomes honestly. DESIGN QUESTION recorded in the migration header for Task 16: should pages be first-class business/brand-scoped?
3. **CSV product import** — importer bound `products.store_id` to `brand_stores` ids (via `useBusinessContext().brandStores`) — wrong id space (RLS first, FK second). **FIXED same day** (`d26c8e5`): picker rebound to `useStoresList()` (operational `stores` = the Products page's space), CTA repointed to Order Sources, payload id-space pinned by `productImportStoreSpace.test.tsx`. **OPEN MODEL QUESTION (needs a user decision):** after the fix a fresh business has no import target — nothing in the UI creates `stores` rows (the Brands-page dialog creates `brand_stores` only; `stores` is really the WooCommerce-connector registry, `url` NOT NULL, and the only provisioner ever was the retired `create_my_brand_store` RPC). Options: **(A)** Brands-page dialog dual-writes a `stores` row + `brands.woo_store_id` link; **(B, recommended)** Woo-connection bridge — creating a woocommerce order source provisions the transitional store + brand link, plus a free "local store" pseudo-connection for pure-CSV merchants; **(C)** repoint the operational key now (= the Task 16 destination, contract-scale blast radius). Manual product add and store-less POS/orders dead-end the same way (products INSERT requires `store_id NOT NULL`; the orders store-less leg is `has_role`-only) — whatever is chosen should cover those too.
   - **DECIDED 2026-11-01 (user): option B** — IMPLEMENTED same day. The Dashboard "No stores in this business" empty state (fail-closed by design) was the user-visible symptom that prompted the decision. Shape: (1) creating a `woocommerce` order source fail-soft-bridges to a transitional `stores` row carrying the source's URL + consumer credentials and stamps `order_sources.legacy_woo_store_id` (new column, migration `20261103090000`); (2) an "Add a local store" convenience in the product-import step provisions a `local://<brand-slug>` row for pure-CSV merchants. **Key RLS fact** (verified `20261026120000:43-61`): `user_can_access_store()` gates on the `brands.woo_store_id` link + membership + selected business — it does NOT consult `user_store_access` (empty grant set = unrestricted in `usePermissions`), so the brand link is load-bearing and NO grant rows are provisioned. Link-when-free: a brand that already has a link keeps it (the new row is only the source's sync record; products bind to the linked store — one catalog store per brand in the transitional model). Sync safety: `local://` rows are created `status='disconnected'` AND `supabase/functions/_shared/store-url-guard.ts` refuses non-http(s) URLs in `woo-sync` / `woo-push` / `woo-webhook`. The stores INSERT leg ("Members can provision stores") is owner/admin/manager ladder bound to `current_business_context()`; staff and context-less sessions fail closed. Pinned by `src/test/operationalStores.test.ts` + `supabase/tests/rls/operational_store_provisioning_test.sql`. Task 16 note: `order_sources.legacy_woo_store_id` joins the drop list with the legacy tables.
   - **LIVE-VERIFIED 2026-11-01 in TEST HUMAN BA** (user's test business, real UI on the live local DB): creating the WooCommerce source "Woo Bridge Live" (https URL + both credentials, no auto-sync) produced the success toast `Store space ready — product pickers and sync can use "Woo Bridge Live".` and the full DB triple — `stores` row (`status='connected'`), `brands.woo_store_id` link, `order_sources.legacy_woo_store_id` stamp — and the Dashboard's "No stores in this business" empty state was replaced by the operational dashboard scoped to "All stores". **The first live attempt hit an RLS landmine**: `.insert().select()` on `stores` re-checks the SELECT policy (`user_can_access_store(id)`) on the newborn row BEFORE the brand link exists, so every member insert failed `new row violates row-level security policy for table "stores"` (42501) regardless of WITH CHECK — fixed by client-side id + bare insert (`f939cd2`; details in [environment-quirks.md](environment-quirks.md)). The fail-soft design proved itself live: the source was saved with an honest toast instead of being lost.
